# Piora for Obsidian

将 Piora 接入 Obsidian 的独立插件方案：Obsidian 负责聊天、笔记上下文和修改确认，Piora 负责模型调用、会话与 Agent 执行。

> 当前状态：本地可用的桌面插件实现，已完成 Remote API、笔记助手会话、流式内容、引用/检索、附件、工具过程和审阅写回链路。正式发行版、许可证和更大规模压力验收仍待确定。仓库内的隔离宿主夹具位于 `.local/obsidian-host-vault`，不包含真实 Vault 内容。

## 目标

- 直接连接 Piora Remote HTTP API，不嵌入网页、不启动第二套 Agent 引擎。
- 在 Obsidian 中聊天、引用笔记、预览差异和确认写回。
- 默认不发送整个 Vault；先支持桌面端、本机连接。

## 开发与安装

需要 Node.js/npm，以及桌面版 Obsidian（manifest 最低版本为 1.11.4）。在仓库根目录执行，PowerShell 使用 npm.cmd 代替 npm：

~~~sh
npm ci --legacy-peer-deps
npm run check
node scripts/install.mjs "D:/example-vault"
~~~

`npm run check` 依次运行 Vitest、TypeScript 检查和 esbuild 打包；不会运行 Piora 的 `next build`。构建产物位于 `dist/`，安装器只复制插件资源，不自动启用插件、不覆盖已有安装，也不修改笔记。

### 使用流程

1. 启动配套 Piora 服务，并在 Piora「设置 → 远程控制」创建专用 Remote Token。
2. 在 Obsidian 桌面版启用 CLI（设置 → 常规 → 高级 → 命令行接口），或从社区插件目录手动启用 Piora。
3. 打开 Piora 侧栏，在设置中填写 `http://127.0.0.1:30141/api/remote/v1` 和 Remote Token，确认 `serverId` 后连接。
4. 使用「新建会话」创建默认 notes 会话；完整 Agent 模式必须显式确认。
5. 在聊天中引用当前笔记、选区或检索结果；需要写回时先查看差异，再确认替换/插入/新建。

### 命令

- `Piora: 打开聊天侧栏`
- `Piora: 新建会话`
- `Piora: 检索并引用笔记`

真实宿主的逐项验收证据和已知限制见 [验收记录](docs/acceptance.zh-CN.md)。

安装器只将 dist 中的 main.js、manifest.json 和 styles.css 安装到目标 Vault 的 .obsidian/plugins/piora-obsidian，不启用插件、不修改笔记或 data.json。已有安装默认拒绝覆盖；明确更新时添加 --replace，旧资源会备份到插件目录。请先使用测试 Vault，并在 Obsidian 的社区插件设置中手动启用 Piora。

在插件设置中填写 Piora 的本机地址与专用能力令牌，点击连接测试，再打开 Piora 聊天侧栏创建会话。地址可带 /api/remote/v1 前缀。完整功能需要 capabilities.read、session.create、session.state.read、session.history.read、session.message.send、session.messages.read、session.events.read、session.steer、session.abort；已有会话仍须令牌授权。

配套 Piora 的「设置 → 远程控制」现在要求为创建权限填写允许的工作目录（一行一个已存在的绝对路径，允许子目录），默认仅允许 notes。将测试 Vault 的路径填入该列表，再在插件中使用同一目录。空目录列表拒绝全部新建；完整 Agent 需要显式允许。默认不授予当前已有会话的访问权限，需另外勾选。旧创建令牌会显示未受限制警告，建议撤销重发。

连接需要配套服务提供 GET /identity。插件先匿名读取 serverId，首次显式连接时信任手动填写的地址，并在发送令牌前保存该地址的身份绑定。后续请求先核对身份并携带 X-Piora-Server-Id；同一端口返回不同 ID 时拒绝继续，旧版服务缺少身份接口也不会自动降级。可在两端设置中比较 ID；这是防误连措施，不是加密服务认证。

如果确实更换实例，在插件设置选择「更换实例绑定」并确认：清空此地址凭证、关闭凭证记忆并断开，随后重新填写新令牌并连接。旧任务回执保留但不跨实例恢复；未知身份的旧回执需在原 Piora 手动核对，不自动归属给首次连接的新实例。地址变化也不会自动搬迁令牌或任务。

侧栏的「设置」会直接打开可编辑连接设置；命令面板提供打开聊天、新建会话、引用当前笔记及引用选区。新建会话命令与侧栏使用相同的模式确认流程。发送或引导等待回执时，可以继续编辑草稿，回执只清理本次已提交内容，不清空后来输入的文本或新增引用。

运行中使用「排队下一轮」提交后续消息，或使用「引导」调整当前运行。排队需要 session.message.send 与 session.messages.read；每会话最多跟踪 10 条未完成命令，每个已连接服务最多保留 100 条回执，以控制轮询和恢复资源。切换回来时会重新核对该会话全部回执，重启不自动重发消息正文。

任务列表提供「取消任务」，要求服务声明 commandCancellation 并授予 session.abort，只取消选定命令。旧版服务未声明时按钮禁用。「停止」仅中止当前运行，不清空后续队列；需要逐条取消不再需要的后续任务。收到取消请求回执不直接删除本地记录，等命令终态校准后再清理。

默认创建 notes 笔记助手会话；服务端未声明该能力时拒绝创建，不静默降级到完整 Agent。支持显式引用当前笔记、选区或逐项选择其他笔记；回复可预览差异并确认替换、插入或新建。替换时快照不匹配会拒绝写入。完整 Agent 模式需要确认，可能绕过插件直接修改文件。

令牌使用宿主 SecretStorage（可用且启用时），否则仅存内存，不写入普通插件配置。关闭秘密存储时，使用宿主 API 将当前连接的保存值设为空，保留本次内存令牌，不动其他地址或 Vault 的凭证。「忘记令牌」同时清空当前连接的内存值并断开连接，但不会撤销 Piora 端令牌或停止后台任务。宿主不提供存储 API 时会提示无法核实历史保存值；清空失败不会假称已完成。这不是对宿主存储介质进行安全擦除的承诺。

普通配置会保存按服务地址、serverId、幂等键分组的多条任务回执元数据，不保存待确认消息正文；旧版单 task 自动迁移成 tasks 数组，但无身份的回执仅保留待核对，损坏记录会报错而不是静默丢弃。重启后的不确定任务需人工核对，解除锁定只移除当前实例的未确认项，不清空已确认任务。

新建会话也有独立恢复回执：发送前保存原工作目录、模式、名称、模型/思考参数、幂等键和 capabilityId，收到结果后保存 sessionId，最近会话选择落盘成功后才清除。普通配置不保存消息正文、笔记内容或令牌。重启后不会自动重发创建请求；侧栏提供「重试原会话创建」和「核对创建回执」，前者复用原参数和原键，已取得 sessionId 时只恢复选择。完整 Agent 恢复仍需确认。

创建回执按地址和 serverId 隔离，同一实例保留一条未完成创建，最多保存 100 个实例的创建记录。换令牌后不会把原创建键转给新令牌，需恢复原令牌或人工核对后清除；清除不会删除已创建会话，再次新建可能产生另一会话。创建中断开连接不会重新打开事件流，迟到的已确认结果仍保存供下次恢复。配套服务须在 capabilities.authentication 中提供 capabilityId。

正文实时显示需要服务声明 contentStreamIdentity=run-sequence-v1，且当前令牌有正文与事件读取权限。缺少该能力时明确显示「历史同步」，不猜测旧快照的运行身份。新版流按 sessionId、streamId、runId、sequence 校验；同一任务的内部 Agent 重试不清空已完成正文，新一轮任务则清空旧正文。会话运行实例重建触发可恢复重连，权限撤销则停止连接；最终历史仍以服务端为准。

## 验证与限制

- npm run check 执行测试、类型检查和 esbuild 打包，不运行 Piora 的 next build。
- node scripts/integration.mjs ../Piora 是 Windows 本机集成检查，需要已安装依赖的配套 Piora 源码；在 .local 中创建隔离副本，使用 30142 端口与模拟模型，不调用真实付费模型。该端口需空闲。
- 已实现会话、正文流、结构化工具卡片、停止/引导、排队及单条取消、多命令恢复、模型选择、笔记引用与确认写回、本地多笔记检索、图片/UTF-8 文本附件、持久化 serverId、连接绑定和本用户目录登记发现；真实宿主与完整压力验收仍未完成。
- 完整 Agent 的工具卡片显示运行中、成功或失败，可展开纯文本输出；刷新进度保留展开状态，最终与历史结果按 toolCallId 合并。缺少终态的历史调用标为「未收到结果」，不猜测成功。服务须声明 toolLifecycle=tool-calls-v1；旧服务保留工具名称摘要。
- 活动快照只保留最近 20 次工具调用，每项输出最多 2000 字符，并提示省略和截断；历史卡片也仅展示 2000 字符预览。工具正文可能含文件内容、路径或其他敏感文本，纯文本渲染和字段白名单不等于内容脱敏；不要向不可信方授权历史读取。
- 侧栏「检索笔记」或命令「本地检索并引用笔记」支持文件名/正文关键词匹配，空格分隔的词必须全部命中，可限定 Vault 内文件夹。只在点击后扫描本地笔记，优先使用已打开编辑器的未保存内容；不调用模型、不自动发送、不保存检索词或索引。逐项点击「加入引用」，发送时才提交选中的笔记。
- 每次检索最多检查 500 个候选、按 8 MiB 读取预算执行、单笔记最多 256 KiB，显示前 20 条相关结果；达到限额或文件跳过时明确提示，请缩小文件夹。隐藏目录、非 Markdown 和越出 Vault 的链接目标不参与。结果摘要不是整篇笔记，加入引用时重新读取全文，发送仍需通过完整请求的 256 KiB 检查。关闭窗口、重新检索或卸载插件会取消旧检索；不是向量/语义搜索或自动整库上下文。
- 自动化替身测试不等于宿主验收；目前没有自动安装到用户 Vault，也没有完成真实编辑器撤销、布局和完整交互验收。

## 发现本机 Piora

在插件设置点击「发现本机 Piora」。插件只读取本用户的 ~/.piora/services 目录登记，再匿名请求已登记地址的 /identity；不扫描端口、不读取或发送令牌。核对地址和服务 ID，点击「选择此实例」并二次确认后，只保存该地址的身份绑定，仍需手动连接。旧地址的令牌、任务回执不迁移，最近会话选择清空；旧数据仍保留。已有绑定不一致时必须走原「更换实例绑定」流程，发现不会覆盖它。

配套 Piora 在 Node 服务启动时依据实际 PORT 登记，每 20 秒续期，登记有效期 90 秒；正常退出尝试删除自己的记录，强制退出的残留会被过滤。未更新的已安装桌面包不一定包含登记功能；更新配套服务并由你正常重启后才可发现，手动地址仍然可用，本插件不启动或重启 Piora。

默认发现目录与 Piora 的会话/凭证数据目录分离，便于同一用户发现多个实例。需要自定义时，在启动 Piora 与 Obsidian 的环境中设置相同的 PIORA_DISCOVERY_DIR；设置 PIORA_DISCOVERY_DISABLED=1 后重启 Piora 可关闭发布。目录不得经过链接；POSIX 需当前用户所有且不允许组/其他用户访问。Windows 依赖用户目录的继承 ACL，插件不审计 ACL，也不把登记文件或自报 ID 当作密码学认证。

每次最多枚举 128 项、核验 16 个候选，最多 2 个并发匿名请求，每个 2 秒；登记和身份响应上限各 4 KiB。无效/过期/不匹配记录跳过，达到限额会提示。关闭、刷新或卸载会取消旧扫描，迟到结果不回填界面。不会删除其他实例的残留记录；残留过多时可能触发限额，可改用手动地址。

## 附件

- 点击「添加文件」选择本机文件，或「Vault 附件」选择库内文件；也可向输入框粘贴/拖入文件。导入只加入待发送列表，不自动发送；列表显示名称、原始字节数，可逐项移除。普通文本粘贴不受影响，不抓取远程图片 URL。
- 当前支持 PNG、JPEG、GIF、WebP 图片，以及 UTF-8 编码的 txt、md、csv、tsv、json、yaml、yml、log 文本。PDF、Office、SVG、HTML 和可执行文件未支持，不静默转成文本或上传。图片核对文件头与扩展名，不在侧栏执行附件内容。
- 单个附件最多 128 KiB，每条消息最多 8 个；包括 Base64、文本转义、笔记、提示词和元数据在内的完整请求仍不得超过 256 KiB。超限需主动缩小图片/精简文本，不自动压缩、截断或拆成多轮。仅附件也可发送，插件会补充分析附件的提示。
- 图片需要配套服务声明 messageImages=base64-images-v1，并选择支持图片输入的模型。源码服务端会对不支持或未声明图片能力的当前模型明确失败，不静默丢图，也不自动切换模型。
- 发送、排队和引导都携带本次附件快照；收到回执只清理本次已提交项，后来新增的附件和草稿保留。内存中的重试保持原图片和幂等键；插件配置/任务回执不保存附件正文或 Base64。重启后仍只恢复回执，不自动重发附件。
- Vault 附件读取前后校验真实路径；隐藏路径、越界链接和不支持的格式拒绝读取。Markdown 附件优先使用已打开编辑器文本。显式选择的外部文件只读取选择器/剪贴板提供的字节，不凭文件名或粘贴链接扩展文件访问。卸载时丢弃未完成导入结果。

## 安全边界

Piora 必须在后台运行。API 令牌不等于执行沙箱，`cwd` 不是安全隔离边界。正式提供安全的笔记助手模式前，需服务端阻止工具、Shell 和扩展绕过修改确认。完整 Agent 模式必须显式启用并说明直接修改文件的风险。

配套 Piora 源码已增加持久化 notes 策略和每令牌创建模式/目录限制：notes 禁用工具与扩展、拒绝 Shell 及提权命令，恢复后继续受限。目录按服务端真实路径校验，但不是 Agent 文件访问沙箱，不会追溯降级已明确授权的完整 Agent 会话。旧令牌缺少创建策略字段时保留兼容行为，必须撤销重发才能获得限制。

正文流和生命周期流均在输出前复核授权；生命周期流空闲时每秒复核，失权发送 REMOTE_ACCESS_ENDED 后关闭，不停止后台任务。生命周期重放积压和输出队列有界，超限以 stream.reset 结束，客户端重连并以状态/历史重新校准。已进入网络缓冲的数据无法撤回；定时检查不是硬实时撤销保证。

serverId 标识 Piora Remote 数据目录，不是进程或端口：共享同一数据目录的进程、目录副本可能共享 ID。匿名 ID 可被恶意本机程序伪造，探测与发送之间也存在竞态；本功能不能防御恶意本机进程或替代 TLS/操作系统隔离，不自动扫描端口。

本仓库尚未提供正式安装包或开源许可证，发行与许可方式仍待确认。
